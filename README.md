# هلا 2034 — ذكاء تشغيلي لتجربة جماهير كأس العالم

منصة تستقبل ملاحظات الجماهير بلغات مختلفة (نصاً أو صوتاً)، تفهمها وتصنّفها، تجمع
البلاغات المتشابهة في مشكلة واحدة، وتعرضها للجهة المنظّمة على لوحة متابعة وخريطة
حرارية مع تنبيهات استباقية ومؤشرات استجابة.

## التشغيل

```bash
npm run dev
```

ثم افتح <http://localhost:3000>.

| `npm run dev` | تشغيل بيئة التطوير |

| `npm run build` | بناء نسخة الإنتاج |
| `npm start` | تشغيل نسخة الإنتاج بعد البناء |
| `npm run lint` | فحص الكود |

## المفهوم المحوري: النوع الفرعي

المحرك لا يكتفي بفئة عامة، بل يستخرج **نوعاً فرعياً مستقلاً عن اللغة** مثل
`facilities:elevator` أو `crowding:congestion`. هذا يحقق أمرين معاً:

1. بلاغ عربي وآخر إنجليزي وثالث إسباني عن نفس المشكلة تحمل كلها نفس النوع الفرعي،
   فتُجمَّع في مشكلة واحدة — وهي ميزة النظام الأساسية.
2. مشكلتان مختلفتان في نفس الفئة والموقع (مصعد معطل / مقاعد مكسورة) تحملان نوعين
   مختلفين، فلا تندمجان في تذكرة واحدة مشوّشة.

مستوى التفصيل مضبوط على **وحدة الإجراء التشغيلي**: الطابور والتكدّس عند بوابة واحدة
نوع واحد لأن الإجراء واحد، بينما المصعد والمقاعد نوعان لأن الإصلاح مختلف.

## مساران للتصنيف

يستدعي التطبيق دالة واحدة: `classifyReport(text, zoneId)` في `lib/classify.ts`.

- **مع مفتاح API**: يُرسل البلاغ إلى `/api/classify`، فيصنّفه Claude بمخرجات منظّمة
  (`output_config.format`) مقيَّدة بقائمة الأنواع الفرعية والمواقع. الفئة تُشتق من
  النوع الفرعي على الخادم فلا يمكن أن يعود النموذج بزوج غير متسق.
- **بلا مفتاح، أو عند أي فشل** (انقطاع شبكة، تجاوز حد الاستخدام، تأخر يزيد عن ٨ ثوانٍ):
  يرتد النظام تلقائياً إلى المحرك المحلي في `lib/ai.ts`. النظام يعمل في كل الأحوال،
  وحقل `source` في النتيجة يبيّن أي محرك أنتجها.

لتفعيل المسار السحابي، أنشئ ملف `.env.local`:

```
ANTHROPIC_API_KEY=sk-ant-...
```

المفتاح يُقرأ على الخادم فقط ولا يصل إلى المتصفح.

## المحرك المحلي

1. **كشف اللغة** — من النظام الكتابي (مع تقديم الكانا على الكانجي) ثم من كلمات دالة.
2. **التصنيف** — قاموس متعدد اللغات لكل نوع فرعي، مع تطبيع للنص العربي (التشكيل،
   الهمزات، التاء المربوطة). عند تعادل عدد المطابقات تفوز العبارة الأطول لأنها الأدلّ.
3. **الخطورة** — كلمات تصعيد + حد أدنى لكل نوع (الحالات الطبية والحريق حرجة دائماً).
4. **الموقع** — من نص البلاغ إن ذُكر، وإلا من الموقع الذي حدّده المستخدم.
5. **التجميع** — نفس النوع الفرعي + نفس الموقع + خلال ٩٠ دقيقة، مع تصعيد تلقائي
   للأولوية عند التكرار (٥ بلاغات ترفع درجة، و١٢ ترفع درجتين).

## التحليلات التشغيلية

- **الاتجاه الزمني** بشرائح ١٥ دقيقة مع مقارنة آخر ساعة بالتي قبلها — هذا ما يكشف
  حادثة تتصاعد، والأعداد المجمّعة وحدها لا تكشفها.
- **مؤشرات الاستجابة**: متوسط زمن أول إجراء، ومهلة مستهدفة لكل درجة خطورة
  (حرج ٥ د، عالي ١٥ د، متوسط ٤٥ د، منخفض ١٢٠ د). المشكلات المتجاوزة تُوسم في القائمة.
- **كشف التصاعد**: ٣ بلاغات أو أكثر على نفس المشكلة خلال ١٥ دقيقة يرفع تنبيهاً
  استباقياً في أعلى اللوحة.

## الاختبارات

```bash
npm test
```

١٩ اختباراً تغطي كشف اللغة، دقة التصنيف، التجميع عبر اللغات، الفصل بين المشكلات

الاختبارات المدمج في Node — بلا أي مكتبة اختبار إضافية.

## تخزين البيانات

الحالة محفوظة في `localStorage` تحت المفتاح `hala2034:state:v2`، وتُبنى بيانات
تجريبية عند أول تشغيل. زر «إعادة تعيين البيانات التجريبية» في لوحة المتابعة يعيد
بناءها.

**قيد مهم:** لكل متصفح نسخته الخاصة من البيانات، فلا تُشارَك بين الأجهزة ولا تُحدَّث
لحظياً بين واجهة الجمهور ولوحة المشرفين. لرفع هذا القيد يُستبدل `lib/store.ts` بقاعدة
بيانات مشتركة (Supabase مثلاً) مع اشتراك لحظي — بقية النظام لا يحتاج تعديلاً.

## ملاحظات

- الإدخال الصوتي يعتمد على Web Speech API — مدعوم في Chrome و Edge، ويحتاج إذن المايكروفون.
- الواجهة عربية بالكامل باتجاه RTL، والخط `IBM Plex Sans Arabic`.
- لوحة تفاصيل المشكلة تُغلق بمفتاح Esc ويُحصر التنقل داخلها ما دامت مفتوحة.
